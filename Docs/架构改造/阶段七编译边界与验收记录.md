# 阶段七编译边界与验收记录

本阶段完成了规则程序集拆分、重复状态清理、旧调用者登记和扩展接入验证。正式工程保留可运行的角色外壳、动画脚本、插件适配和行为树节点。阶段一至六的业务调整、模块流程图、二十八组调用链以及扩展步骤见[重构全览](阶段一至六重构全览与模块调用链.md)。

## 程序集归属与依赖方向

表中箭头从调用者指向其允许引用的项目程序集。正式业务由主程序集连接。规则程序集不能反向引用它。

| 程序集 | 可以引用 | 迁入职责及约束 |
|---|---|---|
| 公共契约 | 无其他项目程序集 | 请求、结果、身份、凭证、快照以及武器、任务和部位枚举。保留向量等基础类型和原有凭证有效期逻辑 |
| 战斗规则 | 公共契约 | 武器运行状态、玩家动作冲突规则、命中部位倍率。编译时禁用引擎引用 |
| 背包规则 | 公共契约 | 物品实例、配置、使用服务、背包和仓库模型。物品资源类型与引擎数值类型仍需要引擎引用，实例写入器只在本程序集可见 |
| 任务规则 | 公共契约 | 波次、计时、存活登记、击杀目标与快照。编译时禁用引擎引用 |
| 规则测试 | 公共契约、战斗规则、背包规则、任务规则 | 编辑器专用。不依赖正式场景控制器。必须检查真实宿主或正式资产的集成测试留在原编辑器程序集 |

五份定义均关闭自动引用预编译插件。构建前置检查验证程序集名称、实际类型归属、依赖白名单、引擎与测试平台设置，并扫描规则调用中出现的场景、组件、时间与资源访问。越界时报告源文件、调用方法、目标和指令偏移。编译器单独限制程序集内部写入器的可见性。[编译与构建校验](../../Assets/Editor/阶段七编译边界.cs) · [边界测试](../../Assets/Editor/架构阶段七边界测试.cs) · [纯规则测试](../../Assets/Editor/规则测试/架构跨程序集规则测试.cs)

## 状态和兼容入口如何收尾

| 入口 | 当前调用者、状态归属及保留理由 | 淘汰条件或新增代码走向 |
|---|---|---|
| 背包、仓库宿主及物品列表 | 背包界面、寄存界面、掉落资源读取器和性能探针仍查询列表。物品实例写入归模型程序集。取出合并、移除等半成品转移入口已从宿主删除 | 仅显示数据的新代码读快照，变更请求交给模型或使用服务。现有网格操作仍要识别具体实例，迁完这些调用者才可去掉旧列表 |
| 玩家当前状态及武器弹量 | 战斗界面、轮盘、准星等依赖旧查询。玩家当前状态由动作与移动投影，弹匣及装填状态从武器运行模块查询 | 新调用者按需读取动作通道和武器快照。旧界面及插件绑定退出后再移除投影 |
| 伤害结算旧倍率查询 | 命中盒和伤害提交仍可使用原签名，宿主查询转发到战斗规则。计算实际扣血的请求结果与倍率结算的表现广播各有消费者 | 新倍率只改战斗规则；删除转发前应迁完命中盒、旧适配及其回归 |
| 武器局部命中通知 | 仍属于旧准星数据接口。项目脚本检索未发现其订阅者。命中普通可伤害物体也可触发并携带基础伤害；血效和准星当前订阅全局敌人命中事实 | 新表现订阅全局事实。确认接口实现、外部消费者和非敌目标通知均已迁移，再一并删除旧签名 |
| 敌人主控制器、动画和行为树入口 | 预制件、序列化行为任务、攻击与移动桥接、旧伤害调用者依赖原类型身份。主控制器转交已迁出的生命、感知、战斗、动作、表现与运动请求，仍承载未拆出的场景适配逻辑 | 新战术意图经动作请求，读取快照。引擎按名称或类型查找的入口须连同使用的资产迁移后才可删除 |
| 章节任务宿主 | 进度界面、波次流程、生成执行和旧测试使用章节宿主。运行中的计时、击杀和波次由任务规则维护，旧属性从配置或规则读取。移除了无人使用的私有别名和导航转发 | 新目标使用章节配置、规则与进度快照。宿主继续负责执行协程、登记生成实例和订阅死亡 |
| 对局旧敌人数及匿名登记 | 具名角色只登记在敌群名册，对局旧查询为名册数量加匿名登记数。无参登记方法仅维护历史无身份来源，保留序列化旧字段迁移。当前项目没有具名角色再调用这两个方法 | 新角色使用敌群具名登记。待旧场景序列化值及外部无参调用确认退出，可移除匿名通道。此数按登记和注销统计，任务剩余敌人数另由任务规则计算 |
| 界面自动补引、楼梯准备及旧单例 | 两个界面或教学的自动补引方法、旧静态楼梯准备方法未发现项目脚本调用。正式场景由启动入口显式绑定。旧界面和表现仍通过已有宿主查询本局对象 | 新场景由启动入口验证引用，新面板订阅已有宿主并释放许可。去掉无调用入口前应核对编辑器工具、序列化事件与外部反射 |

旧角色脚本、命名空间、行为树和动画资源身份保留。十三个已有脚本带原元文件迁移，逐个核对元文件字节。跨程序集的物品配置等序列化类型标记原程序集来源。武器类型从角色文件提取，原枚举名称与数值保留。正式场景、敌人预制件、配置和物品共十九份登记资源的摘要与迁移前一致。[脚本迁移映射](检查结果/阶段七/脚本迁移路径.json) · [资源身份核对](检查结果/阶段七/资源身份核对.json)

## 复验与回退

编辑器测试窗口筛选“架构”，运行编辑器测试；打开正式主场景，从“工具／敌人智能／验证行为树与状态契约”运行集成校验。单独复验扩展接入时进入运行模式，执行上表接入脚本。它重载正式场景后仅修改内存中的模板与章节副本，结束时退出运行模式。附加界面和三号房复验各从原配置的全新主场景开始。构建可通过[独立构建脚本](阶段七独立构建.cs.txt)在编辑状态执行。

[清单](检查结果/阶段七/迁移清单.json)为每条源码、程序集定义及元文件路径记录迁移前后摘要，[基线归档](基线/阶段七/源码及元文件.zip)保留迁移前字节。运行[源码回退工具](阶段七源码回退.py)默认预览；关闭目标编辑器后加 `--应用` 才会成组恢复。它核对当前值、阻止覆盖后续新增内容。恢复后应重开编辑器并复查编译、资源引用与主场景。这次隔离回退验证范围为源码及元文件。

## 人工与性能验收边界

动画过渡的观感、镜头回正、开火与收刀手感、声音衔接仍沿用[阶段六人工清单](阶段六剩余验收与人工操作清单.md)，需实际游玩签收。阶段七构建与运行回归没有测量同设备前后三轮的帧耗时和逐帧分配。阶段六六轮样本中第一组帧耗时超预算，分配门槛也未通过，不能由本轮功能验收关闭。[阶段六性能证据](阶段六性能与补充验收记录.md)

原计划登记的普通敌人挥空补判及战斗中硬直衰减进入阶段八单独修复与验收。新增敌人变体和章节配置本轮均已通过正式生成链；新增武器、关卡、通路与界面的接入步骤见[重构全览的扩展说明](阶段一至六重构全览与模块调用链.md#四怎样沿新边界扩展)。
